# متطلبات ميزة نقل المصروفات التشغيلية

## المقدمة

هذا المستند يوضح المتطلبات الوظيفية لميزة نقل المصروفات التشغيلية من المحاسب المالي إلى الخزينة والمصارف.

## المتطلبات الوظيفية

### المتطلب 1: عرض المصروفات المعلقة

**القصة المستخدم:**
كمحاسب مالي، أريد عرض قائمة بجميع المصروفات التشغيلية التي لم يتم نقلها بعد، حتى أتمكن من اختيار المصروفات المراد نقلها.

**معايير القبول:**
1. يتم عرض جدول يحتوي على جميع المصروفات بحالة `pending`
2. الجدول يعرض: الوصف، الفئة، المبلغ، التاريخ، الملاحظات
3. كل صف يحتوي على خانة اختيار
4. إذا لم تكن هناك مصروفات معلقة، يتم عرض رسالة "لا توجد مصروفات معلقة"
5. يتم تحديث الجدول تلقائياً عند تحميل الصفحة

### المتطلب 2: اختيار مصروفات متعددة

**القصة المستخدم:**
كمحاسب مالي، أريد اختيار مصروفة واحدة أو أكثر من الجدول، حتى أتمكن من نقلها معاً.

**معايير القبول:**
1. يمكن اختيار مصروفة واحدة أو أكثر باستخدام خانات الاختيار
2. يتم حساب المبلغ الإجمالي للمصروفات المختارة تلقائياً
3. يتم عرض المبلغ الإجمالي في واجهة النقل
4. يمكن إلغاء الاختيار بسهولة

### المتطلب 3: تحديد وجهة النقل

**القصة المستخدم:**
كمحاسب مالي، أريد تحديد ما إذا كانت المصروفات ستُنقل إلى خزينة أو مصرف، حتى أتمكن من تنظيم النقل بشكل صحيح.

**معايير القبول:**
1. يتم عرض قائمة منسدلة بخيارين: "خزينة" و"مصرف"
2. يجب اختيار وجهة واحدة قبل النقل
3. عند اختيار وجهة، يتم تفعيل حقل تفاصيل الوجهة

### المتطلب 4: إدخال تفاصيل الوجهة

**القصة المستخدم:**
كمحاسب مالي، أريد إدخال تفاصيل الوجهة (اسم الخزينة أو المصرف والحساب)، حتى يتم تسجيل المعلومات بشكل دقيق.

**معايير القبول:**
1. يتم عرض حقل نص لإدخال تفاصيل الوجهة
2. الحقل يقبل نصاً حراً (اسم الخزينة أو المصرف والحساب)
3. الحقل مطلوب قبل النقل
4. يتم التحقق من عدم ترك الحقل فارغاً

### المتطلب 5: إضافة رقم مرجع اختياري

**القصة المستخدم:**
كمحاسب مالي، أريد إضافة رقم مرجع اختياري (رقم الحوالة أو الشيك)، حتى يتم تتبع العملية بسهولة.

**معايير القبول:**
1. يتم عرض حقل نص اختياري لرقم المرجع
2. الحقل يقبل أي نص
3. الحقل غير مطلوب
4. يتم حفظ رقم المرجع مع سجل النقل

### المتطلب 6: نقل المصروفات

**القصة المستخدم:**
كمحاسب مالي، أريد نقل المصروفات المختارة إلى الوجهة المحددة، حتى يتم تسجيل العملية في النظام.

**معايير القبول:**
1. يتم عرض زر "نقل المصروفات"
2. الزر يكون معطلاً إذا لم يتم اختيار مصروفات أو وجهة
3. عند النقر على الزر، يتم إرسال طلب POST إلى الخادم
4. يتم عرض رسالة تأكيد النجاح
5. يتم تحديث الجدول بعد النقل الناجح
6. يتم مسح الاختيارات بعد النقل

### المتطلب 7: عرض سجل المصروفات المنقولة

**القصة المستخدم:**
كمحاسب مالي، أريد عرض سجل بجميع المصروفات التي تم نقلها، حتى أتمكن من تتبع العمليات السابقة.

**معايير القبول:**
1. يتم عرض تبويب منفصل للمصروفات المنقولة
2. الجدول يعرض: الوصف، الفئة، المبلغ، الوجهة، تفاصيل الوجهة، رقم المرجع، تاريخ النقل، الحالة
3. يتم عرض أيقونة مناسبة لكل وجهة (خزينة/مصرف)
4. يتم عرض الحالة بألوان مختلفة (مكتملة/معلقة)
5. إذا لم تكن هناك مصروفات منقولة، يتم عرض رسالة "لا توجد مصروفات منقولة"

## المتطلبات غير الوظيفية

### الأمان
- الميزة محمية بصلاحية `/reports/expenses`
- يتم التحقق من الصلاحيات قبل عرض الميزة
- يتم التحقق من الصلاحيات قبل تنفيذ عملية النقل

### الأداء
- يتم جلب البيانات بكفاءة من الخادم
- يتم عرض رسالة تحميل أثناء جلب البيانات
- يتم تحديث الجدول بسرعة بعد النقل

### سهولة الاستخدام
- الواجهة بديهية وسهلة الاستخدام
- يتم عرض رسائل خطأ واضحة
- يتم عرض رسائل تأكيد النجاح

### التوافقية
- الميزة متوافقة مع جميع المتصفحات الحديثة
- الميزة متوافقة مع الأجهزة المحمولة

## الافتراضات والقيود

### الافتراضات
1. الخادم يوفر جميع واجهات برمجية الخادم المطلوبة
2. المستخدم لديه صلاحية `/reports/expenses`
3. قاعدة البيانات تحتوي على مصروفات معلقة

### القيود
1. يمكن نقل مصروفات متعددة في عملية واحدة فقط
2. لا يمكن تعديل المصروفات بعد النقل
3. لا يمكن إلغاء عملية نقل بعد تنفيذها
